## Decisions

- **`@source` path corrected to four levels** (plan-review correction, verified against the repo): `apps/web/src/app` → root is `../../../../`; the plan's three-level path (`apps/packages/ui/src`) does not exist. The same depth applies to the `tokens.css` import.
- **The CSS gate needs two markers — single-marker `focus-ring` false-passes.** Empirical negative proof during implementation: with `@source` removed and only the `tokens.css` import left, the built CSS still contained `.focus-ring` (the utility's own name appears inside the imported stylesheet) while component-source utilities (`bg-success-bg`, `border-line-strong`, `bg-brand-strong`) were **missing** — pages would render unstyled exactly as feared, yet a focus-ring-only gate stayed green. The gate therefore asserts `bg-success-bg` (proves the `@source` scan reaches packages/ui React sources) in addition to `focus-ring`, validates both markers' uniqueness against apps/web sources at runtime, and the negative case was executed: `@source` removed → gate exit 1 with a pointed message; restored → gate ok.
- **TanStack Table pinned to v8 (`^8.21.3`), core API, no hooks.** v9 is latest (9.3.1) but its breaking changes are unvetted here. `useReactTable` requires a client component, and the opinionated column API includes `render` functions — not serializable across the server→client boundary from a server page. The framework-agnostic core (`createTable` + `getCoreRowModel`) renders in RSC with zero client JS. v8.21.3's `createTable` takes `TableOptionsResolved` and its `setOptions` returns void, so the adapter pattern from `useReactTable` is replicated: create with dummy `state/onStateChange/renderFallbackValue`, then `table.setOptions(prev => ({...prev, state: table.initialState}))` — without the swap, `getHeaderGroups()` throws on missing `columnPinning` state.
- **Pagination links via injected `PageLinkComponent`** — packages/ui must not depend on next; apps/web passes `Link` (structurally assignable since Link accepts a superset of `PageLinkProps`), keeping client-side routing and prefetch. Disabled edges render non-interactive spans so the control keeps its shape.
- **`page_size < 1` falls back to the default (20), not clamped to 1** — mirroring procurement's `ValidateList` (`f.PageSize < 1 { f.PageSize = DefaultPageSize }`); caught by the table-driven test (first implementation clamped and failed it).
- **Default locale `id`** per the PRD's "ID + EN" ordering (plan assumption); flipping is a one-line change in review.
- **Field gained a `select` control variant** so the tenant switcher's local label+select markup lands on the design system without a separate Select component.
- **apps/web-local interactive elements keep the browser's default focus-visible outline** (SidebarNav links, raw selects outside Field): the keyboard-focus requirement is met without diluting the gate marker (`focus-ring` stays packages/ui-only; the gate enforces that split every run).
- **packages/ui devDependency set** mirrors apps/web (typescript, vitest, @vitejs/plugin-react, @testing-library/react, jsdom, eslint, eslint-config-next, @eslint/eslintrc, @types/react(-dom)/node, react/react-dom for tests) — plan-review correction: without react/@types declared, `tsc --noEmit` and component tests cannot run under the isolated linker.
- **100k-row claim is stub-proven, and said so** — `DataTable.test.tsx` builds a `total = 100_000` / `pageSize = 50` stub and asserts only the requested slice renders (rows V-000101…V-000150 for page 3, neighbours absent, exactly 50 `<tr>`); `TablePagination.test.tsx` asserts the derived `{from:1,to:50,total:100000,pageCount:2000}`. The live tenant holds 3 vendors (seeded via the gateway as in dev-note 050; the seed tool writes the isolated `demo` schema — `TRUNCATE demo.*` at scripts/seed/main.go:460 and `CopyFrom pgx.Identifier{"demo", …}` at :487 — so live 100k data is unreachable without touching the seed, which this issue does not).
- **Metadata stays English** (`title`/`description` in the root layout) — not screen copy; noted as a follow-up rather than widening this diff.
- Dev-note filename follows the zero-padded convention (013–050): `051-design-system-tables-i18n.md`.

## Follow-ups

- Localize the root layout `metadata` (title/description) if/when per-locale metadata matters.
- `SidebarNav` links still use the browser default focus ring; a future design pass could adopt a shared ring style without breaking the gate (pick a new packages/ui-only marker then).
- Pagination offers prev/next only; numbered page links (and a page-size picker) arrive with the interactive vendor/requisition screens, where TanStack's stateful features (sorting/filters) will also mount — the core-only server table today keeps `state`/`onStateChange` as inert placeholders.
- Real keyboard/screen-reader pass (manual or Playwright+aXe) once e2e lands (M4); this issue proves focus visibility structurally (focus-ring on every interactive component, compiled into CSS) rather than with an assistive-tech run.
- apps/web compose integration remains out of scope (050 follow-up); `next start` was used for the live smoke above.
