# 050 — Next.js app shell, auth flow, and tenant switcher

- **Issue:** #50
- **Branch:** feature/50-web-app-shell-auth
- **Date:** 2026-10-23

## What

- **Gateway public auth API** — `services/gateway/server/auth.go` (new): `POST /api/v1/auth/login`, `POST /api/v1/auth/refresh`, `POST /api/v1/auth/logout`, proxied to identity gRPC through the new `IdentityClient` interface + `WithIdentity` option (pattern of `VendorClient`/`WithProcurement`; the identity conn was already dialed in `cmd/gateway/main.go`). Dedicated error mapper `authError` (not the shared `grpcHTTPError`, which has no `ResourceExhausted` arm): InvalidArgument→400, Unauthenticated→401 (identity's generic anti-enumeration text passes through), ResourceExhausted→429 + `Retry-After`, default→502 `identity unavailable`. Logout is idempotent (204, empty body succeeds silently). `services/gateway/server/auth_test.go` is table-driven over all three routes plus the limiter and the public/protected routing split.
- **Server.go routing fix required for public auth** — the old `v1 := app.Group("/api/v1", bearerAuth(verifier))` attaches middleware that matches *every* `/api/v1/*` path by prefix, so `/api/v1/auth/login` answered 401 (proven by `TestAuthWiringThroughNew` during development). `/api/v1/me` now attaches `bearerAuth` per route; vendors/requisitions keep their own groups. No behavior change for protected routes.
- **Login rate limiting** — per-IP in-memory token bucket (`internal/platform/ratelimit`) on the gateway login route, `GATEWAY_LOGIN_RATE_PER_MIN` in `services/gateway/config/config.go` with an explicit default of 30/min; 429 + computed `Retry-After`. identity is untouched (its 5/min per-email limiter stays as defense in depth).
- **apps/web is a real Next.js App Router app** (replaces the placeholder; `src/index.ts` deleted): root layout + corporate shell with the full PRD §11 sidebar — Dashboard, Requisitions, Approvals, Purchase Orders, Vendors, Invoices, Reports, plus an Admin group (Users, Settings) rendered only when claims include `admin` (`RoleAdmin`). `/` redirects to `/app/dashboard`; requisitions/approvals/purchase-orders/invoices/reports/admin pages render through a shared `PlaceholderPage`, so no sidebar link 404s. `/app/vendors` is a server component fetching `GET /api/v1/vendors` (#27) — the tenant-isolation proof page. Tailwind v4, strict TypeScript; `packages/config` and `packages/ui` untouched.
- **Route structure** (fixes a plan defect found in review): the plan's `src/app/(app)/dashboard/page.tsx` would serve `/dashboard` — route groups add no URL segment — while PRD §11 requires `/app/dashboard`, `/app/vendors`, `/admin/users`, … Pages therefore live at `src/app/(app)/app/<section>/page.tsx` and `src/app/(app)/admin/<section>/page.tsx`, with the shell layout at `src/app/(app)/layout.tsx`; the `(app)` group shares the shell across `/app/*` and `/admin/*` without adding a segment.
- **Session via httpOnly cookies** (`eproc_at`, `eproc_rt`) written **only in route handlers** — `src/app/api/auth/{login,logout,refresh,switch-tenant}/route.ts` — because Next.js forbids `cookies().set()` outside Server Actions/Route Handlers. Server components hydrate claims via `GET /api/v1/me` (`GATEWAY_URL`, default `http://localhost:8080`, read per request; pages are `force-dynamic`). Expired access token (local `exp` decode from the base64url payload, **no signature verification** — a navigation decision only; verification stays at the gateway per ADR-0001) or a 401 from `/me` redirects to `/api/auth/refresh?next=<path>`; that handler rotates the cookies legally and 303-redirects back; failure clears cookies and lands on `/login?next=` (401) or keeps them and lands on `/login` (gateway down).
- **Middleware** (`src/middleware.ts`) is a presence check only: include-list matcher `["/app/:path*", "/admin/:path*", "/login"]`, so `/_next/*`, `/favicon.ico`, and `/api/auth/*` (all POSTs) never pass through and are never converted into redirects; no session → 307 (NextResponse.redirect default, not 302) to `/login?next=<path>`; session on `/login` → 307 to the dashboard. `next` is validated same-origin (`safeNext` in `src/lib/redirect.ts` — open-redirect guard).
- **Single-flight refresh** (`src/lib/refresh-singleflight.ts`): all refreshes funnel through one in-process module — a Map of in-flight promises keyed by the old refresh token plus a ~60 s result cache, so concurrent callers holding the same refresh token (two tabs, layout + page) produce exactly one `POST /api/v1/auth/refresh`. This exists because identity's rotation semantics revoke the whole token family when a rotated token is replayed (docs/schema/identity.md) — a racing double refresh would kill the session. Pinned by an explicit vitest race test.
- **Demo tenant switcher** (maintainer decision 2026-10-23): entries from `DEMO_TENANTS` (`slug=email` pairs); switching POSTs to `/api/auth/switch-tenant`, which re-logs in server-side with the target admin's email + `DEMO_ADMIN_PASSWORD` and rotates the cookies in the handler, then the client does a full navigation so every list reloads scoped to the new tenant. Empty password → JSON redirect to `/login?email=…` (prefilled); gateway 401/429 on the re-login → `/login?email=…&error=switch_failed`. `scripts/seed` and `compose.yaml` untouched (decisions 1–2 in the issue; ADR-0003).
- **Env wiring that Next actually reads** — `next dev/build` loads `apps/web/.env.local` only, not the root `.env`. Convention: `apps/web/.env.local` for real local values (git-ignored: `git check-ignore apps/web/.env.local` → ignored by `.gitignore` `.env.*`), committed `apps/web/.env.example` with placeholders and no secrets (`git check-ignore apps/web/.env.example` → exit 1, committable). Root `.env.example` gained `GATEWAY_LOGIN_RATE_PER_MIN=30` and a pointer comment. No dotenv dependency (AGENTS rule 10).
- **Docs** — `docs/onboarding.md` §5.1 "Demo tenant admins, the web shell, and tenant-scoped app data": create two admins via `cmd/useradmin`, log in per tenant via `POST /api/v1/auth/login`, seed 2–3 vendors per tenant via `POST /api/v1/vendors` (409 `vendor_duplicate_code` on rerun is ignorable), run `pnpm dev`, verify the vendor list differs per tenant. Without these steps `procurement.vendors` is empty (the seed only writes the isolated `demo` schema) and both tenants show empty lists.

## Decisions

- **Login rate limiting = Option A, agent-applied** (provenance corrected per plan review): the issue thread records this as "Decision applied by agent (2026-10-23, maintainer unavailable — override welcome in PR review)", *not* a maintainer decision — flagging here so the PR review actually examines it. Basis: ADR-0001 assigns rate limiting to the gateway; PRD §17 (line 379) requires throttling on auth endpoints; identity stays untouched. The per-IP bucket sees only the BFF's loopback IP in the local demo (effectively per-BFF-instance), documented in both `.env.example` files; X-Forwarded-For parsing is a follow-up if the gateway is ever exposed directly.
- **`authError` mapping is a deliberate superset of identity's `mapAuthError`** (plan-review correction): identity's mapper (services/identity/server/api.go) has no InvalidArgument arm — empty email/password surface as `ErrInvalidCredentials` → Unauthenticated. The gateway's 400 arm therefore only fires from *local* body validation (missing fields / malformed JSON), never from identity. Keeping the arm is still correct: it documents the contract and costs nothing.
- **Per-route bearerAuth instead of restructuring paths**: keeping PRD §15's `/api/v1/auth/*` paths (rather than moving auth outside `/api/v1`) is the smaller diff; attaching the verifier per route avoids the prefix-matching trap entirely.
- **Refresh dance lands on the page path when a page triggers it, `/app/dashboard` when the layout does** — layouts do not know their pathname. Whichever `requireSession` runs first wins; in practice the layout's call fires first on navigations, so an expiry-triggered refresh bounces off the dashboard. Acceptable for the demo; noted rather than engineered around (a pathname-aware solution needs headers()/user-agent cooperation).
- **JSON responses + client navigation for login/logout/switch, 303 redirect only for the refresh dance**: fetch follows redirects opaquely, so handlers that browsers trigger via fetch return `{redirect}` and the client does `window.location.assign`; the refresh dance is a browser *navigation* (307/303 semantics matter there).
- **In-process single-flight is adequate** for the single-instance BFF demo (compose integration of apps/web is out of scope per maintainer decision 2); multi-instance needs a shared store — follow-up.
- **Next pinned to 15.5** (not 16.x): 16 renames the middleware convention (`proxy.ts`); the issue and plan specify `src/middleware.ts`, and 15.5 is the mature line for it. React 19, Tailwind v4 (`@tailwindcss/postcss`, no config file), ESLint 9 flat config via `FlatCompat` + `eslint-config-next`, `eslint.ignoreDuringBuilds` so `next build` and the `pnpm lint` gate stay independent. vitest + @testing-library/react + jsdom per maintainer decision (2026-10-23); `@testing-library/jest-dom` intentionally not added (assertions use plain `textContent`).
- **TanStack Query/Table and Zustand/RHF not pulled in yet**: the shell is server-component reads + one form; the interactive screens (PRD §20 stack) arrive with their milestones — keeps this diff reviewable.
- **Admin gating is presentational**: the sidebar renders the Admin group only for admins and the admin pages render an "Administrators only" notice for non-admins, but real enforcement stays at the gateway/service RBAC (`users:manage` is admin-only in the matrix) — defense in depth, matching FR-01.
- **Dev-note filename** follows the repo's zero-padded convention (013–029): `050-web-app-shell-auth.md`.

## Follow-ups

- **Rate limiting provenance**: maintainer should confirm Option A in PR review (agent-applied, see Decisions). If the gateway is ever exposed directly (not only via the BFF), parse `X-Forwarded-For` for the limiter key and consider a shared (Redis) bucket across gateway replicas.
- **apps/web compose integration** — maintainer decision 2 keeps it out of scope; a `web` service (profile `demo`) plus a production build image is the natural next step.
- Single-flight refresh is per-process; multi-instance BFF needs a shared dedup (Redis lock or a token-version cache).
- Refresh dance from the shell layout lands on `/app/dashboard` (layouts lack the pathname); a `headers()`- or middleware-driven `next` could restore the exact page.
- Access tokens stay valid up to 15 min after logout (PRD §17 Redis revocation list is a later issue); the shell signs out fully only after that window.
- i18n (UI copy ID + EN, PRD §19) is not wired; current copy is English only.
- `GATEWAY_LOGIN_RATE_PER_MIN` uses the burst=per-minute-value convention; if a tighter burst is ever needed, split rate and burst into two env vars.
